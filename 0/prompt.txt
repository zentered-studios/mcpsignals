  #### [MEDIUM — found and fixed during this audit] Race in Python tool-hint cache produced wrong telemetry under concurrent calls
  - **Location:** `packages/python/src/mcpsignals/instrument.py` (the `listed` boolean in commit `2fc7ad8`, superseded by commit `8f0d4f4`)
  - **Description:** In `2fc7ad8`, `_hints_for()` set a module-scoped `listed = True` flag *before* the `await server.list_tools()` it guards had resolved. Two `tools/call` requests for different, not-yet-cached tool names, running concurrently via `asyncio.gather` (ordinary client behavior, not an attack), could interleave so the second one saw `listed == True` and returned `(None, None)` immediately instead of waiting for the in-flight listing.
  - **Impact:** Telemetry integrity only — `read_only_hint`/`destructive_hint` recorded as null for a tool that does declare them, under ordinary concurrent traffic. No data leaked to the client, no crash, no unbounded memory.
  - **Proof of concept:** I reproduced it directly. Running the full Python suite at `2fc7ad8`+ (before the fix) failed intermittently:

    (1 failure in 9 full-suite runs; the isolated test alone always passed, confirming it's a genuine interleaving-dependent race, not flaky test infra.)
  - **Status: already fixed.** Commit `8f0d4f4` (landed mid-audit) replaces the boolean with a shared `asyncio.Task`, and concurrent misses `await asyncio.shield(task)` on the same task instead of racing a flag.   #### [LOW] `RegisteredTool.update({ name })` to a colliding name silently reassigns the wrong `registeredTools` entry
  - **Location:** `packages/node/src/instrument.ts:286-305`
  - **Description:** The new rename-tracking wrapper does `registeredTools.set(updates.name, registration)` without checking whether `updates.name` already maps to a *different* tool's registration. If host code renames tool A to a name that collides with tool B, B's entry in `registeredTools` is silently overwritten by A's, so subsequent calls to B (if the SDK still resolves it, e.g. by object identity elsewhere) would record A's `read_only_hint`/`destructive_hint`/`canInject` settings.
